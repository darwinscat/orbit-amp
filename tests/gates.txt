# THE GATES — the one list every runner runs: the pull request's CI (.github/workflows/build.yml), the
# family's release on every system it builds on (.github/workflows/release.yml), and the local release
# (installer/release.sh). A release with a red gate is not a release. Taking a gate in, or out, is a line
# here and nowhere else.
#
# One gate a line:   <name>  <target>  [VAR=value ...]  [skip=<system>[,<system>]]
#
#   <name>     what the runner calls it, and the name of its log (<build>/gates/<name>.log)
#   <target>   the CMake target that builds it; CMakeLists.txt refuses a name that is no target, and
#              `--target Family_Gates` builds every gate of the list. Most are orbitamp_gates, the one
#              program that holds them (CMakeLists.txt: THE GATES BINARY), run with ORBITAMP_GATE=<name>
#   VAR=value  set in the gate's environment, and nowhere else
#   skip=      the systems it does NOT run on — macos, windows, linux — each with its reason in a
#              comment above the line.
#
# Every gate runs in a home of its own, made empty for it (tools/run-gates.sh), so a gate that writes
# where a player's amp would — the family's Factory folder, the player's IRs — writes into that home,
# never the runner's or the machine's owner's. (On Windows the home is the runner's own profile: Windows
# finds AppData without asking the environment. The workflows run the gates only on hosted runners,
# which are thrown away after the job.)

# The site's kit of OrbitAmp's face is written on a Mac (ORBITAMP_WEB_EXPORT, through CoreGraphics); on
# Windows JUCE's own renderer and PNG codec leave a knob's antialiased edges up to 94/255 off when its sprite
# is laid back over the cabin — a kit nobody writes there. Red on Windows since it came (PR #77).
# And off on the Mac too until the kit learns OrbitAmp's new face (0.9.0): the channel lever and its names,

# the cabin is not the poster less its live parts. The site keeps the kit it has until then.
